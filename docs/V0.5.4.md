# V0.5.4 Pixel Polish Plan

## Status

**PLANNING ONLY**

Functional V0.5 is complete through V0.5.3. V0.5.4 is the next visual polish phase, but implementation must wait for Sola's explicit approval.

## Goal

Make the completed V0.5 tracker feel more like a tiny cozy pixel-game daily log while preserving the real accessible web app underneath.

Pixel Polish should improve charm, composition, responsiveness, and consistency. It should not add new tracker features, analytics, data models, or V1 systems.

## Scope

V0.5.4 planning may cover:

- Stronger Today clipboard / daily quest board presentation.
- Stronger History notebook / scrapbook presentation.
- Stronger Progress chart board / graph-paper presentation.
- A cohesive decorative icon and motif direction.
- A possible small mascot/static pose direction.
- Mobile and desktop visual QA priorities.
- Accessibility and reduced-motion polish.
- Original/licensed asset needs.

## Non-Scope

Do not include:

- New database tables or migrations.
- Supabase configuration changes.
- New analytics, goals, BMI, forecasts, reports, or correlations.
- Achievements, XP, levels, rewards, badges, currency, leaderboards, or challenges.
- V1 habit/routine builders or broad V1 navigation.
- Game engine behavior, player movement, or elaborate animation systems.
- Use of `.codex-remote-attachments/` or planning reference images as app assets.

## Visual Principles

- Keep the existing cream/paper surfaces, dark chunky outlines, shadows, pink/yellow/green accents, and cozy pixel-game feeling.
- Preserve real controls: inputs, buttons, checkboxes, file uploads, chart points, and links remain functional HTML.
- Pixel decoration should frame and support the UI rather than replace important text or controls.
- Prefer compact, readable, personal-product layouts over ultrawide stretching.
- Avoid generic SaaS dashboards, clinical wellness-app styling, glassmorphism, and huge decorative gradients.

## Surface Plan

### Today

Planning direction:

- Refine the daily check-in as a pixel clipboard or quest board.
- Keep the checklist and fields compact and scannable.
- Preserve the monthly calendar and streak side panels.
- Consider small original icon treatments for checklist groups and daily fields.
- Keep mobile stacked, thumb-friendly, and free of horizontal overflow.

### History

Planning direction:

- Refine daily entries as notebook pages.
- Refine food photos as a scrapbook/gallery.
- Keep large photo viewing and previous/next navigation clear and accessible.
- Add delight through frame treatments, paper tabs, stickers, or motifs only if they do not reduce usability.

### Progress

Planning direction:

- Refine the chart board and graph-paper presentation.
- Keep Detail and All Time modes readable.
- Keep recorded and missing-date markers visually distinct.
- Preserve the tracking footer and summary-card hierarchy.
- Leave room for a possible mascot/static pose near the chart without crowding the graph.

## Mascot / Character Direction

A mascot is optional for V0.5.4. If approved later, it should be:

- Small and decorative.
- Static or limited to a few simple poses.
- Original, licensed, or otherwise safe to use.
- Replaceable without changing product logic.
- Never required to understand or operate the app.

Possible static contexts:

- Today: holding a clipboard or standing by the quest board.
- History: reading a notebook or pointing at scrapbook photos.
- Progress: pointing at the chart board.

## Suggested Planning Milestones

1. Visual audit:
   - Capture current desktop and mobile screenshots.
   - Identify the highest-impact polish opportunities per screen.

2. Asset direction:
   - Decide whether to use pure CSS/pixel UI motifs first, commission/create original pixel assets, or combine both.
   - Decide whether a mascot belongs in V0.5.4 or later.

3. Design-system polish:
   - Define small reusable treatments for tabs, labels, icon slots, cards, chart frames, scrapbook frames, and empty states.

4. Screen polish plan:
   - Plan Today, History, and Progress changes in small reviewable implementation slices.

5. QA plan:
   - Define desktop/mobile viewport checks, accessibility checks, reduced-motion expectations, and no-overflow checks.

## Implementation Gate

Do not implement V0.5.4 until Sola explicitly approves a Pixel Polish implementation task.
